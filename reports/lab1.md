# 实验一：多道程序与分时多任务

## 实现概要

为每个任务保存独立的系统调用计数，在系统调用分发前更新，确保本次 trace 也计入统计。实现 trace 的单字节读取、低八位写入和调用次数查询，非法请求返回 -1。计数表使用堆分配，避免扩大固定大小的内核栈。本章尚无地址空间隔离，按题目要求直接访问地址。

## 简答题

1. 使用仓库提供的 RustSBI 0.4.1。用户态执行 `sret` 或访问 `sstatus` 等 S 态寄存器会触发 IllegalInstruction；访问非法地址会触发访问异常。内核在 trap_handler 中终止出错应用，随后调度其他应用，不应让一个应用的错误结束整个系统。实际测例结果见下方验证记录。
2. `__restore` 入口的 sp 指向内核栈上的 TrapContext。它既用于首次启动任务时恢复预先构造的上下文，也用于系统调用、中断或任务切换后返回用户态。
3. 特殊恢复的是 sstatus、sepc 和用户 sp：sstatus 的 SPP 决定返回特权级，sepc 决定恢复执行的位置，用户 sp 先放入 sscratch，最后与内核 sp 交换。t0/t1/t2 只是搬运这些值的临时寄存器。
4. x2 是栈指针，需要在所有内核栈访存结束后通过交换恢复，不能直接与普通寄存器一起加载；x4 是 tp，本章用户程序不使用线程指针，因此框架跳过它。
5. `csrrw sp, sscratch, sp` 后，sp 为用户栈指针，sscratch 保存内核栈顶，供下一次 trap 使用。
6. `sret` 完成 S 到 U 的特权级切换；预先构造或保存的 sstatus.SPP 为 User，CPU 按此恢复特权级，并跳到 sepc。
7. `__alltraps` 开头交换后，sp 为内核栈顶，sscratch 为陷入时的用户 sp，之后才能在内核栈上保存 TrapContext。
8. 用户程序执行 `ecall`、触发异常，或收到已启用的中断时，硬件先进入 S 态并跳到 stvec；特权级切换发生在陷入的硬件流程中，`__alltraps` 的第一条指令已经运行在 S 态。

## 验证

使用 nightly-2024-05-02、QEMU 8.2.2、RustSBI 0.4.1 和官方 rCore-Tutorial-Checker 验证。通过临时 PATH 包装器在 Docker 中运行 QEMU，测试命令为 `PATH=/tmp/rcore-tools:$PATH make -C ci-user test CHAPTER=3`。检查器输出 7/7，报告检查通过，命令退出码为 0。框架在所有应用退出后打印 `All applications completed!`，这是本章原有结束路径。
